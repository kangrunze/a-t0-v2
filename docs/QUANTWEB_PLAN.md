# QuantWeb — A-T0 回测平台方案

## 一、项目概述

QuantWeb 是一个基于 Streamlit 的 Web 回测平台，旨在让用户通过浏览器界面完成策略配置、回测执行、结果分析和参数优化全流程，替代当前仅依赖命令行和 HTML 报告的交互方式。

## 三、现状（已实现，Phase 1）

### 3.1 已完成的页面

| 页面 | 功能 | 状态 |
|------|------|------|
| **综合仪表盘** | 总回测次数、完成数、盈利运行数；最近 10 次运行列表；最近一次运行的个股净盈亏柱状图、胜率 vs 净盈亏散点图 | ✅ 基础 |
| **回测配置** | 股票池选择、日期范围、底仓股数；参数覆盖滑块（alpha_threshold_open 等 7 个参数）；后台线程异步执行 | ✅ 基础 |
| **结果查看** | 运行选择器、状态卡片、汇总指标；4 个 Tab：个股净盈亏、胜率分布、CE 分析、个股明细；CSV 下载 | ✅ 基础 |
| **策略对比** | 多选运行对比、汇总指标表、雷达图、个股净盈亏对比柱状图、参数配置对比 | ✅ 基础 |
| **参数配置** | 七维度权重滑块编辑、信号参数只读展示、风险参数展示、原始 YAML 编辑+验证 | ✅ 基础 |

### 3.2 已实现的数据库层

- `runs` 表：回测运行记录
- `results` 表：个股结果摘要（含 V2 指标）
- `daily_results` 表：逐日明细
- `config_snapshots` 表：配置快照
- `optuna_trials` 表：Optuna 试验记录

### 3.3 当前差距

| 功能 | 现状 | 缺失 |
|------|------|------|
| 回测执行 | 后台线程，页面需手动刷新 | 无实时进度推送 |
| 结果保存 | 通过 `save_result()` 保存 | 未保存逐日 PnL 序列 |
| Optuna 集成 | 独立命令行脚本 | 未对接 Web UI |
| 数据缓存 | 每次查询都读 SQLite | 无缓存层 |
| 报告生成 | 依赖 HTML 报告 | 未集成到 Web 界面 |
| 权限控制 | 无 | 单用户模式，暂不急需 |

## 四、Phase 2 迭代计划

### Phase 2.1 — 核心体验完善（1-2 天）

**目标**：让回测配置-执行-查看的闭环更流畅

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 回测进度实时推送 | 使用 `st.empty()` + 轮询或 Server-Sent Events 显示当前进度（第 X/Y 只股票，耗时） |
| P0 | 结果页面自动刷新 | 检测运行状态，running 时每 5s 自动刷新 |
| P1 | 回测参数预设 | 支持保存/加载参数组合（如 "Baseline"、"Optuna 最优"、"激进"、"保守"） |
| P1 | 运行标签/分组 | 支持给回测运行打标签，按标签筛选 |
| P1 | 配置保存时自动快照 | 每次保存配置时自动记录快照到 `config_snapshots` 表 |

### Phase 2.2 — Optuna 集成（1-2 天）

**目标**：在 Web 界面中启动、监控和管理 Optuna 优化

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | Optuna 优化启动页 | 设置搜索空间、股票池、日期范围、trial 数 |
| P1 | 优化进度实时展示 | 显示当前 trial、最佳 objective、参数重要性热力图 |
| P1 | 最优参数一键应用 | 点击按钮将最优参数写入 thresholds.yaml |
| P2 | 参数平行坐标图 | 用 Plotly 平行坐标展示参数与 objective 的关系 |
| P2 | 多 study 对比 | 对比不同研究的优化效果 |

### Phase 2.3 — 高级分析（2-3 天）

**目标**：提供更深入的分析能力

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | K 线图与交易标记 | 选择个股，显示 K 线 + 入场/出场标记 |
| P0 | 资金曲线 | 累计 PnL 曲线、回撤曲线 |
| P1 | 分组对比 | 按标签/策略分组聚合对比（如 "Baseline" vs "Optuna"） |
| P1 | 指标筛选 | 按净盈亏、胜率、CE 等指标筛选股票 |
| P2 | 自定义指标公式 | 允许用户输入公式计算自定义指标 |
| P2 | 报告导出 PDF | 将当前页面导出为 PDF 报告 |

### Phase 2.4 — 数据与管理（1-2 天）

**目标**：数据管理和系统维护

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P1 | 运行记录管理 | 删除/重命名/备注运行记录 |
| P1 | 数据统计 | 各 Engine 的 IC 分析、因子衰减曲线 |
| P2 | 批量回测 | 一次配置多个参数组合，排队执行 |
| P2 | 定时任务 | 支持定时执行回测并推送结果 |

## 五、技术细节

### 5.1 数据流

```
用户配置 → save_run() → 后台线程执行 run_zz500_batch()
  → per_stock 结果 → save_result() 写入 SQLite
  → 前端轮询 get_run() 获取状态
  → 完成时显示结果
```

### 5.2 关键依赖

- **Streamlit 1.28+** — Web 框架
- **Plotly 5.18+** — 交互式图表
- **Pandas 2.0+** — 数据处理
- **SQLite3** — 结果持久化
- **PyYAML 6.0+** — 配置解析
- **Optuna 3.0+** — 参数优化（后台）

### 5.3 启动方式

```bash
# 开发模式
streamlit run web/app.py --server.port 8501

# 生产模式（建议）
streamlit run web/app.py --server.port 8501 --server.headless true
```

### 5.4 目录结构

```
web/
├── app.py              # 入口 + 导航
├── results_db.py        # 数据库层
├── pages/
│   ├── __init__.py
│   ├── dashboard.py     # 综合仪表盘
│   ├── backtest.py      # 回测配置
│   ├── results.py       # 结果查看
│   ├── compare.py       # 策略对比
│   └── config.py        # 参数配置
data/
└── quantweb.db          # SQLite 数据库（自动创建）
```

## 六、技术选型说明

### 为什么选 Streamlit 而非其他框架？

| 方案 | 优点 | 缺点 | 适合度 |
|------|------|------|--------|
| **Streamlit** | 纯 Python，开发快，与数据科学生态无缝集成 | 不适合复杂交互，多用户支持弱 | ⭐⭐⭐⭐⭐ |
| **Dash** | 更灵活，适合复杂交互 | 学习曲线陡，代码量大 | ⭐⭐⭐ |
| **Flask + Vue** | 完全可控 | 前后端分离成本高 | ⭐⭐ |
| **Gradio** | 快速原型 | 缺乏定制化 | ⭐⭐ |

### 数据量预估

- 单次回测 100 只股票 × 3 年：约 500 条结果记录
- 50 次运行：约 25,000 条记录
- SQLite 完全胜任（预计 < 10MB）
