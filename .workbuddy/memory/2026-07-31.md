- 证据：`outputs/backtest/batch_summary_w_wave_v1.json` 与 `batch_summary_v3_b5_optimized.json` **逐字节相同**（net_pnl 均为 152.14，per_stock 完全一致）。
- 根因：`backtest.py` 的 alpha 分支只注入 `_direction`，未注入 `_bars`；而 `score/alpha_score.py:443` 是
  `bars = snap.get("_bars", []); engines = _get_engines() if bars else {}`
  → 回测里 engines 恒为 {}，Wave / Support / ExpectedMove / Regime / Risk **五个 Engine 从未执行**（实盘 `evaluate_all_signals` 却是执行的，两边口径不一致）。
- 影响：**此前所有 Engine 级 A/B（含 w_wave_v1）结论全部无效**，必须在修复后重跑。

## 测量口径修正（哨兵值 Bug，本日发现并修复）
项目约定：**指标不可用一律返回 `None`，禁止用 -1 / 0 兼作哨兵。**
- `entry_delay_bars = -1` 是合法值（比极值早 1 根入场 = 最优入场），旧代码 `if v != -1` 过滤会**系统性剔除最好的入场样本**，把 Entry Delay 分布整体推高。
- `exit_delay_bars = 0` 是合法值（恰在极值K线平仓 = 完美退出），旧代码用 0 表示不可用。
- `wave_number = 0` 非法（波数从 1 起算），旧代码用 0 表示不可用，会拉低分布。
- batch 聚合旧代码 `if v > 0` 会剔除负的 Entry Delay / Execution Gain（提前入场、成交优于理想价的好样本）→ 改为按 `pair_count > 0` 纳入。
